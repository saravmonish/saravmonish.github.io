Deep Learning · Security

Deep CNN Encoder-Decoder for Secure Image Steganography

Published · Scopus Indexed
Python TensorFlow Keras OpenCV Flask

Traditional steganography methods like LSB insertion are easy to attack — they have low payload capacity and are detected quickly by steganalysis tools. This paper proposes a CNN-based encoder-decoder that hides data inside images with nearly undetectable visual change, trained on 10,000 images to handle real-world distortions like compression, noise, and scaling.

The encoder extracts deep spatial features from the cover image and embeds the secret payload across them. The decoder reverses this precisely, even after the image has been manipulated. A composite loss function balances two objectives simultaneously — keeping the image visually identical to the original (MSE) while maximising data recovery accuracy (Binary Cross-Entropy).

Cover + secret → CNN encoder → Stego imagevisually identical → Compression · noise → CNN decoder → Recovered data
38.2 dB PSNR — well above the 30 dB quality threshold
0.95 SSIM score — images visually indistinguishable from originals
92% Data retrieval accuracy after JPEG compression

Steganalysis detection rate kept below 30% — meaning adversaries struggle to even confirm hidden data exists. The system also maintained 88% accuracy under Gaussian noise and 85% after 50% image scaling, with a maximum payload of 1KB per image.

Computer Vision · Deep Learning

EcoScan: Detecting Micro-Plastics in Waterways

Python YOLOv8 CBAM PyTorch OpenCV

Micro-plastics — particles smaller than 5mm — blend into sediment, surface reflections, and organic matter. They're translucent, tiny, and nearly impossible for a standard detection model to pick out in drone footage of a river.

I extended YOLOv8 with Convolutional Block Attention Modules (CBAM) inserted directly after the C2f backbone blocks, before the multi-scale fusion stage. This forces the network to suppress background noise — glare, ripples, colour variation — and amplify the faint signals left by translucent particles, rather than treating everything equally. Prior work only adds attention at the detection head; putting it earlier means the benefit carries through every downstream stage.

Drone frame → YOLOv8 backboneC2f blocks → CBAM attentionsuppresses noise → Multi-scale fusion → Detections
10,000+ Labeled training images
6 Debris classes (bottles, bags, foam, nets, other, micro-plastics)
4.9% Micro-plastic share — severe class imbalance addressed with focal loss

Training handled a sharp imbalance — micro-plastics are only 4.9% of annotations while macro-plastics account for 56%. I used focal loss to stop the model from ignoring them entirely, then oversampled micro-plastic examples with domain-specific augmentations: simulated murky water (brownish-green tint), Gaussian blur for camera defocus, and gamma correction to replicate changing light. YOLOv8's mosaic augmentation added further context diversity.

Data-Efficient Industrial Defect Detection Using RGB Images and 3D Geometry

Ongoing · Research project
PythonPyTorchOpen3DEfficientNet-B0PatchCore

Defects can appear as changes in surface colour, texture, or shape. I'm investigating whether combining RGB images with 3D geometry improves industrial anomaly detection when only a limited number of defect-free training examples are available.

The study uses MVTec 3D-AD, initially focusing on bagel, carrot, and cookie objects. The planned approach aligns EfficientNet-B0 visual features with Fast Point Feature Histograms (FPFH) describing local 3D geometry. A PatchCore-style memory bank of normal features provides a reference for scoring new objects and locating potential defects.

RGB + 3D scans → EfficientNet + FPFHappearance and geometry → Feature fusionaligned descriptors → Normal memory bank → Anomaly score + map
3Object categories in the initial study
3Planned training-data levels: 25%, 50%, and 100%
5Methods planned for comparison

Ongoing work. The evaluation will compare feature fusion with RGB-only, 3D-only, late-fusion, and RGB autoencoder baselines across three random seeds. Planned measures include image-level AUROC, pixel-level AUROC and AUPRO, runtime, and memory use. Results will be added after the experiments are complete.

Illicit Bitcoin Transaction Detection Under Temporal Shift

Ongoing · Research project
PythonPyTorchPyTorch GeometricGraphSAGEscikit-learn

A drop in detection precision does not always mean a model has stopped learning useful patterns. When illicit transactions become rarer, precision can fall even without a comparable change in the model's ability to distinguish them. I'm studying how to separate model degradation from changes in the underlying illicit-transaction rate.

Using the Elliptic transaction graph, the study compares Logistic Regression, Random Forest, a multilayer perceptron, and GraphSAGE to examine whether graph connections add value over transaction features. Chronological training, validation, and test windows keep future observations out of model fitting and tuning.

Elliptic graph → Chronological splittrain / validate / test → Feature vs. graph models → Per-step evaluation → Base-rate analysis
203,769Transaction nodes in the Elliptic dataset
49Time steps for chronological evaluation
4Feature-based and graph-based models in the study

Ongoing work. The evaluation plan uses time steps 1–30 for training, 31–34 for validation, and 35–49 for testing. Per-step precision–recall performance and illicit-class F1 will be analysed alongside class prevalence, calibration, and bootstrap uncertainty. An unlabelled drift monitor is a stretch goal; final findings are not yet reported here.
